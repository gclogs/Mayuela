# 현상수배 리드 격차 기반 설계

## 목적

현상수배는 1등 팀을 무조건 처벌하는 시스템이 아니라, 선두 팀이 의미 있는 격차를 만들었을 때 추격 팀에게 역전 동기를 제공하는 밸런스 장치입니다.

잘못 조정되면 다음 문제가 생깁니다.

- 1등을 하는 순간 계속 벌을 받아 선두 플레이가 불쾌해짐
- 현상수배 보상이 너무 커서 일부러 1등을 피하는 플레이가 생김
- 현상수배 기준이 모호해서 운영자가 밸런스 원인을 분석할 수 없음
- 현상수배가 너무 자주 켜지고 꺼져 UI와 메시지가 피로해짐

따라서 현상수배는 `1등 여부`가 아니라 `1등 + 명확한 리드 격차 + 최소 진행 조건`을 모두 만족할 때만 발동합니다.

## 핵심 원칙

- 현상수배 대상은 최대 1팀입니다.
- 현상수배 대상은 현재 1등 팀만 될 수 있습니다.
- 현재 1등이라고 해서 무조건 현상수배가 되지 않습니다.
- 1등과 2등의 누적 활성화율 격차가 설정값 이상일 때만 발동합니다.
- 초반 우연한 선두를 처벌하지 않기 위해 최소 게임 시간과 최소 진행률을 둡니다.
- 발동 기준과 해제 기준을 다르게 둬서 현상수배가 깜빡거리듯 반복되지 않게 합니다.

## 기준 지표

### 1등 판정

1등 팀은 다음 순서로 결정합니다.

1. 누적 활성화율이 높은 팀
2. 누적 활성화율이 같으면 점령 누적 시간이 긴 팀
3. 그래도 같으면 팀 ID 정렬

이 기준은 현재 스코어보드 랭킹 정렬과 동일하게 유지하는 것이 좋습니다.

### 리드 격차

```text
리드 격차 = 1등 팀 누적 활성화율 - 2등 팀 누적 활성화율
```

예시:

```text
빨강 34.0%
파랑 22.5%
리드 격차 = 11.5%
```

## 권장 기본 설정

```yaml
bounty:
  enabled: true
  warmup-seconds: 120
  min-leader-activation-percent: 20.0
  activate-gap-percent: 10.0
  release-gap-percent: 7.0
  transition-cooldown-seconds: 30
  reward-coins: 8
  reward-once-per-target: true
```

## 발동 조건

모든 조건을 만족해야 현상수배가 발동합니다.

- 게임 페이즈가 `PLAYING`입니다.
- 현상수배 기능이 활성화되어 있습니다.
- 팀이 2개 이상 존재합니다.
- 게임 시작 후 `warmup-seconds` 이상 지났습니다.
- 1등 팀의 누적 활성화율이 `min-leader-activation-percent` 이상입니다.
- 1등과 2등의 누적 활성화율 차이가 `activate-gap-percent` 이상입니다.
- 마지막 현상수배 상태 변경 후 `transition-cooldown-seconds` 이상 지났습니다.

## 해제 조건

다음 중 하나라도 만족하면 현상수배를 해제합니다.

- 현상수배 팀이 더 이상 1등이 아닙니다.
- 1등과 2등의 격차가 `release-gap-percent` 이하로 줄어듭니다.
- 게임이 종료되거나 초기화됩니다.
- 현상수배 기능이 비활성화됩니다.

`activate-gap-percent`와 `release-gap-percent`를 다르게 두는 이유는, 격차가 11.9%와 12.1% 사이에서 계속 흔들릴 때 현상수배가 반복 발동/해제되는 문제를 막기 위해서입니다.

## 보상 규칙

- 현상수배 상태의 플레이어를 다른 팀 플레이어가 처치하면 코인 8개를 지급합니다.
- 같은 팀 처치는 보상을 지급하지 않습니다.
- 같은 현상수배 플레이어를 처치해서 보상을 이미 받았다면, 해당 현상수배 상태에서는 다시 보상을 받을 수 없습니다.
- 현상수배가 해제된 뒤 다시 발동하면 보상 지급 이력은 초기화됩니다.
- 보상 코인은 실제 인벤토리에 들어가는 Mayuela 코인 아이템이어야 합니다.

## UI 표시

- 스코어보드에 현상수배 팀을 표시합니다.
- 보스바 또는 스코어보드에는 가능하면 리드 격차를 함께 표시합니다.
- 현상수배 플레이어 머리 위에는 기존 팀 색상 `ItemDisplay`를 유지합니다.
- 팀 색상 `ItemDisplay` 아래에는 `TextDisplay`로 `현상수배` 문구를 표시합니다.
- 현상수배 플레이어는 팀 색상 발광 효과를 얻습니다.

## 메시지

### 발동

```text
[현상수배] 빨강 팀이 현상수배 상태가 되었습니다.
```

### 해제

```text
[현상수배 해제] 빨강 팀의 리드 격차가 6.8%로 줄어들었습니다.
```

### 보상 지급

```text
현상수배 보상으로 코인 8개를 획득했습니다: PlayerName
```

### 이미 지급됨

```text
PlayerName님의 현상수배 보상은 이미 지급되었습니다.
```

## 모니터링 지표

현상수배 밸런스 검증을 위해 다음 값을 매치 통계에 저장해야 합니다.

- 현상수배 발동 시점
- 현상수배 해제 시점
- 1등 팀
- 2등 팀
- 1등 누적 활성화율
- 2등 누적 활성화율
- 리드 격차
- 발동/해제 사유
- 현상수배 중 처치 횟수
- 실제 보상 지급 횟수
- 보상 지급 대상 플레이어

운영자 모니터링 명령어에는 다음 값을 출력합니다.

- 현재 1등 팀
- 현재 2등 팀
- 현재 리드 격차
- 현상수배 발동 가능 여부
- 발동 불가 사유
- 현재 현상수배 팀

## 개발 설계

### 설정

`game.yml`에 `bounty.*` 설정을 추가합니다.

관리자 명령어는 후속으로 다음 형태를 권장합니다.

```text
/game 현상수배설정 격차 <퍼센트>
/game 현상수배설정 해제격차 <퍼센트>
/game 현상수배설정 준비시간 <초>
/game 현상수배설정 최소진행률 <퍼센트>
/game 현상수배설정 보상 <코인>
```

### 상태 소유권

- `GameTeam`: 현재 현상수배 여부와 보상 지급 이력
- `AltarService` 또는 별도 `BountyService`: 현상수배 발동/해제 판정
- `ScoreboardService`: 현상수배 팀 표시
- `DisplayService`: 현상수배 머리 위 표시
- `PlayerLifecycleListener`: 현상수배 대상 처치 보상 지급
- `MatchStatsService`: 현상수배 이벤트와 보상 이벤트 기록

### 판정 시점

현상수배 판정은 매 tick이 아니라 제단 활성화율이 갱신되는 주기에서만 수행합니다.

현재 구조에서는 `AltarService.tickActivation()` 이후가 적절합니다.

```text
tickActivation()
  -> 팀별 활성화율 증가
  -> 랭킹 계산
  -> 현상수배 상태 평가
  -> 스코어보드 갱신
```

이 방식은 TPS 부담을 줄이고, 현상수배 기준이 스코어보드 랭킹과 같은 타이밍에 갱신되도록 만듭니다.

## 밸런스 해석

권장 기본값 기준:

- 초반 2분 동안은 현상수배가 발동하지 않습니다.
- 선두가 20% 이상 진행하기 전에는 현상수배가 발동하지 않습니다.
- 1등과 2등 차이가 10% 이상 벌어져야 발동합니다.
- 격차가 7% 이하로 줄어들면 해제됩니다.

이 구조는 다음 의도를 가집니다.

- 초반 우연한 1등 처벌 방지
- 진짜로 앞서가는 팀에게만 리스크 부여
- 추격 팀이 킬을 통해 경제 보상을 얻을 수 있게 함
- 선두 팀이 현상수배를 감수하고 빠르게 끝내는 선택지도 유지

## 튜닝 가이드

| 문제 | 조정 방향 |
| --- | --- |
| 현상수배가 너무 자주 발동됨 | `activate-gap-percent` 증가, `warmup-seconds` 증가 |
| 현상수배가 거의 발동하지 않음 | `activate-gap-percent` 감소, `min-leader-activation-percent` 감소 |
| 1등이 너무 고통받음 | `reward-coins` 감소, `release-gap-percent` 증가 |
| 역전이 거의 안 나옴 | `reward-coins` 증가, `activate-gap-percent` 감소 |
| 현상수배가 켜졌다 꺼졌다 반복됨 | `transition-cooldown-seconds` 증가, `release-gap-percent` 감소 |

## 구현 전 결정 필요 사항

- 기본 발동 격차는 10%로 확정합니다.
- 보상 코인은 현재 상점 가격 기준으로 8개로 확정합니다.
- 현상수배 표시 문구에는 리드 격차를 노출하지 않고 운영자 모니터링에서만 확인합니다.

## 구현 확정 사항

- 기본 발동 격차는 `10.0%`입니다.
- 현상수배 처치 보상은 현재 상점 가격 기준으로 `8코인`입니다.
- 리드 격차 수치는 일반 플레이어 메시지, 스코어보드, 머리 위 표시에는 노출하지 않습니다.
- 리드 격차 수치는 운영자 `/game 모니터링` 출력에서만 확인합니다.
