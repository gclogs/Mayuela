## 문서 관리 규칙

- 게임 규칙은 시스템별 문서에 작성합니다.
- Paper API 이벤트명, YAML 필드, 구현 메모는 관련 시스템 문서의 "구현 메모"에 작성합니다.
- 여러 시스템에 영향을 주는 내용은 [[10-구현-체크리스트]]에도 작업 항목을 추가합니다.
- 구조 또는 성능 판단이 필요한 경우 [[11-개발-원칙]]을 우선 기준으로 삼습니다.
- 중요한 기술 결정은 [[15-ADR-가이드]] 형식으로 기록합니다.
- 상태 원본이 애매하면 [[17-런타임-상태-소유권]]을 먼저 확인합니다.
- 개발 변경사항은 [[CHANGELOG]]에 기록합니다.
- `alter.yml`은 현재 요구사항에 맞춰 그대로 표기합니다. 실제 구현 전 `altar.yml`로 교정할지 결정이 필요합니다.
