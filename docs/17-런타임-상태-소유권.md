# 런타임 상태 소유권

## 문서 역할

게임 중 변하는 데이터를 누가 가지고 있고, 언제 저장하는지 정의합니다.  
이 문서가 없으면 같은 상태를 여러 클래스가 각각 들고 있다가 버그가 생기기 쉽습니다.

## 핵심 원칙

- 게임 중 자주 바뀌는 값은 메모리 상태로 관리합니다.
- YAML은 설정과 안정 상태 저장에 사용합니다.
- 같은 데이터의 원본은 하나만 둡니다.
- UI는 상태를 소유하지 않고 상태를 읽어서 표시만 합니다.

## 상태 종류

| 상태 종류 | 설명 | 예시 |
| --- | --- | --- |
| 설정 상태 | 서버 재시작 후에도 유지되는 설정 | 로비 위치, 맵 위치, 제단 위치 |
| 런타임 상태 | 게임 중에만 의미 있는 상태 | 현재 점령자, 활성화율, task id |
| 플레이어 상태 | 참가자별 게임 상태 | 준비 상태, 코인, 점령 제단 |
| 표시 상태 | Display 엔티티와 UI 상태 | TextDisplay UUID, 스코어보드 |

## 상태 소유권 표

| 데이터 | 소유 컴포넌트 | 저장 위치 | 저장 시점 |
| --- | --- | --- | --- |
| 현재 게임 세션 | `GameSessionService` | 메모리 | 저장하지 않음 |
| 참가 플레이어 목록 | `GamePlayerService` | 메모리 | 게임 종료 시 초기화 |
| 팀 수동 지정 | `TeamService` | 메모리 | 운영자 `/game 팀지정`, `/game 팀해제` 실행 시 |
| 팀 색상 | `TeamService` | 메모리 | 게임 시작 시 확정 |
| 플레이어 코인 | `CoinService` | 메모리, 필요 시 `players.yml` | 게임 종료 또는 구매 시점 |
| 누적 활성화율 | `ActivationService` | 메모리 | 기본적으로 저장하지 않음 |
| 점령한 제단 목록 | `AltarService` | 메모리 | 게임 종료 시 초기화 |
| 등록된 제단 위치 | `AltarService` | `alter.yml` | 제단 등록 명령어 실행 시 |
| 맵 pos1/pos2 | `MapService` | `maps.yml` | 맵 저장 명령어 실행 시 |
| 로비 위치 | `LobbyService` | `game.yml` | 로비 등록 명령어 실행 시 |
| 아이템 정의 | `InventoryService` | `items.yml` | 서버 시작 시 로드 |
| 머리 위 ItemDisplay | `DisplayService` | 메모리 | 게임 종료 시 제거 |
| 제단 위 TextDisplay | `DisplayService` | 메모리 | 게임 종료 시 제거 |
| Scheduler task id | `SchedulerService` | 메모리 | 게임 종료 시 cancel |

## 메모리 상태와 YAML 상태 구분

### YAML에 저장할 것

- 맵 위치
- 로비 위치
- 제단 등록 위치
- 상점 NPC 위치
- 아이템 정의
- 기본 설정값

### YAML에 저장하지 않을 것

- 현재 게임 phase
- 현재 활성화율
- 현재 제단 점령자
- 현재 Display 엔티티 UUID
- 현재 scheduler task id

단, 서버 재시작 후 게임 복구 기능을 만들 계획이 생기면 별도 ADR을 작성합니다.

## UI 상태 규칙

스코어보드, lore, TextDisplay는 원본 상태가 아닙니다.  
항상 `GamePlayerService`, `AltarService`, `ActivationService`의 상태를 읽어서 표시합니다.

좋은 흐름:

```text
ActivationService 상태 변경
-> ScoreboardService 갱신
-> InventoryService lore 갱신
-> DisplayService TextDisplay 갱신
```

나쁜 흐름:

```text
ScoreboardService가 활성화율을 자체 계산
TextDisplay 텍스트를 읽어서 게임 상태 판단
```
