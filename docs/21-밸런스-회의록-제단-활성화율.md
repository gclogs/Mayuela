# 제단 활성화율 밸런스 회의록

## 문서 역할

Mayuela의 제단 활성화율 밸런스를 어떤 기준으로 맞출지 정리한 가상 실무 회의 문서입니다.  
목표는 `2vs2`, `2vs2vs2vs2`, `2vs2vs2vs2vs2` 구조에서 게임이 너무 허무하게 끝나지 않고, 제단 교전과 역전 가능성이 살아 있는 경기 시간을 만드는 것입니다.

## 회의 안건

1. 현재 5개 제단을 모두 점령하면 왜 3~4분 안에 게임이 끝나는가
2. 밸런스의 기준을 무엇으로 잡을 것인가
3. 팀 수와 제단 수가 달라져도 같은 재미를 유지하려면 어떤 공식이 필요한가
4. 운영자가 조정해야 할 설정값은 무엇인가
5. 1인 개발 테스트에서는 어떤 지표를 기록해야 하는가

## 참석 역할

| 역할 | 관점 |
| --- | --- |
| 게임 디렉터 | 경기 재미, 승리까지의 감정 곡선 |
| 시스템 기획자 | 승리 공식, 제단 수, 역전 가능성 |
| PvP 밸런스 담당 | 교전 빈도, 제단 방어/탈환 시간 |
| 서버 개발자 | 구현 복잡도, 설정 가능성, TPS 영향 |
| QA 담당 | 테스트 시나리오, 재현 가능한 측정 기준 |
| 라이브 운영 담당 | 운영자가 조정할 수 있는 안전한 설정값 |

## 현재 문제 요약

현재 기본 공식은 다음과 같습니다.

```text
초당 활성화율 증가량 = base-increase-per-altar * 점령 제단 수
```

현재 기본값이 `base-increase-per-altar: 0.2`라면:

| 점령 제단 수 | 초당 증가량 | 이론상 100% 도달 시간 |
| ---: | ---: | ---: |
| 1개 | 0.2% | 500초, 8분 20초 |
| 2개 | 0.4% | 250초, 4분 10초 |
| 3개 | 0.6% | 167초, 2분 47초 |
| 4개 | 0.8% | 125초, 2분 5초 |
| 5개 | 1.0% | 100초, 1분 40초 |

따라서 5개 제단을 한 팀이 빠르게 가져가면 게임은 2분 안팎으로 끝납니다.  
초반 이동, 교전, 재점령 시간을 포함해도 3~4분 종료가 발생할 수 있습니다.

## 팀별 의견

### 게임 디렉터 의견

Mayuela는 제단을 많이 먹으면 빨라지는 구조가 핵심입니다.  
다만 제단 5개를 모두 먹는 순간 게임이 사실상 끝나면, 다른 팀은 반격할 시간을 갖기 어렵습니다.

권장 감정 곡선:

- 0~2분: 팀 색상 확정, 이동, 첫 제단 점령
- 2~6분: 제단 1~2개를 둘러싼 교전과 코인 수급
- 6~10분: 상위 팀 견제, 제단 탈환, 장비 차이 발생
- 10~12분: 승리 후보 확정, 마지막 방어/공격

따라서 평균 경기 시간은 8~12분을 1차 목표로 잡는 것이 좋습니다.

### 시스템 기획자 의견

밸런스 기준은 `전체 제단을 모두 먹었을 때 걸리는 시간`이 아니라, **현실적으로 유지 가능한 평균 점령 제단 수**여야 합니다.

2인 팀이 장시간 안정적으로 유지할 수 있는 제단 수는 보통 다음처럼 봅니다.

| 팀 수 | 플레이 구조 | 한 팀의 평균 유지 제단 |
| ---: | --- | ---: |
| 2팀 | `2vs2` | 2~3개 |
| 4팀 | `2vs2vs2vs2` | 1~2개 |
| 5팀 | `2vs2vs2vs2vs2` | 1~2개 |

권장 기준:

```text
목표 승리 시간 = 10분
기준 점령 제단 수 = 2개
```

이 경우 기본 증가량은 다음처럼 역산합니다.

```text
base-increase-per-altar = 100 / (목표 초 * 기준 제단 수)
base = 100 / (600초 * 2개)
base = 0.0833%
```

즉 1개 제단당 초당 약 `0.08%`가 10분 경기의 기준값입니다.

### PvP 밸런스 담당 의견

제단 5개 풀점령은 강한 우위 상태이므로 빨라지는 것은 맞습니다.  
그러나 풀점령 상태에서도 상대가 한 번은 반응할 시간이 필요합니다.

`base-increase-per-altar: 0.08` 기준:

| 점령 제단 수 | 초당 증가량 | 100% 도달 시간 |
| ---: | ---: | ---: |
| 1개 | 0.08% | 1250초, 20분 50초 |
| 2개 | 0.16% | 625초, 10분 25초 |
| 3개 | 0.24% | 417초, 6분 57초 |
| 4개 | 0.32% | 313초, 5분 13초 |
| 5개 | 0.40% | 250초, 4분 10초 |

이 수치라면 5개를 모두 먹어도 바로 끝나지 않고, 다른 팀이 탈환할 여지가 있습니다.  
동시에 2개 이상을 오래 유지하면 확실히 승리 압박이 생깁니다.

### 서버 개발자 의견

공식은 복잡하게 바꾸기보다 설정값을 명확히 두는 편이 좋습니다.

현재 공식:

```text
base * capturedAltars
```

이 공식은 이해하기 쉽고 TPS 비용도 낮습니다.  
단기적으로는 `base-increase-per-altar` 기본값을 `0.08`로 낮추는 것이 가장 안전합니다.

중기적으로는 다음 설정을 추가할 수 있습니다.

```yaml
altar:
  activation-tick-seconds: 1
  base-increase-per-altar: 0.08
  max-increase-per-second: 0.35
```

`max-increase-per-second`를 두면 5개 제단 풀점령 시에도 너무 빨라지는 상한을 걸 수 있습니다.  
다만 현재 MVP에서는 수치 튜닝을 먼저 하고, 상한 공식은 2차 밸런스 패치로 미루는 것이 좋습니다.

### QA 담당 의견

밸런스는 체감이 중요하므로 테스트 기록 양식이 필요합니다.

각 테스트마다 다음 값을 기록합니다.

| 기록 항목 | 예시 |
| --- | --- |
| 참가 구조 | `2vs2`, `2vs2vs2vs2`, `2vs2vs2vs2vs2` |
| 총 제단 수 | 5개 |
| base 증가량 | 0.08 |
| 첫 제단 점령 시간 | 00:45 |
| 첫 50% 도달 시간 | 06:10 |
| 최종 승리 시간 | 10:42 |
| 승리 팀 평균 점령 제단 | 2.1개 |
| 최대 순간 점령 제단 | 4개 |
| 교전 체감 | 너무 빠름 / 적당 / 늘어짐 |

1인 로컬 검증에서는 서비스 테스트와 통계 시뮬레이션으로 수치 흐름을 확인하고, 교전 체감은 실제 4인 이상 테스트에서 확인합니다.

### 라이브 운영 담당 의견

운영자가 안전하게 만질 수 있는 값은 많지 않아야 합니다.

운영자에게 노출할 1차 조정값:

- `altar.base-increase-per-altar`
- `altar.activation-tick-seconds`

권장 프리셋:

| 프리셋 | 목표 | base |
| --- | --- | ---: |
| 빠른 테스트 | 기능 확인용 | 0.20 |
| 기본 운영 | 8~12분 경기 | 0.08 |
| 장기전 | 12~15분 경기 | 0.06 |

## 회의 결론

Mayuela의 밸런스 기준은 다음으로 정합니다.

```text
기준 경기 시간: 8~12분
기준 점령 제단 수: 한 팀이 평균 2개 제단을 유지하는 상황
기준 공식: base-increase-per-altar * 점령 제단 수
권장 기본값: base-increase-per-altar = 0.08
```

즉 `5개를 다 먹으면 빨라진다`는 구조는 유지하되, 5개를 모두 먹어도 최소 4분 정도는 버티게 만들어 반격 시간을 보장합니다.

## 권장 설정

```yaml
altar:
  activation-tick-seconds: 1
  base-increase-per-altar: 0.08
```

예상 시간:

| 점령 제단 수 | 초당 증가량 | 100% 도달 시간 |
| ---: | ---: | ---: |
| 1개 | 0.08% | 약 20분 50초 |
| 2개 | 0.16% | 약 10분 25초 |
| 3개 | 0.24% | 약 6분 57초 |
| 4개 | 0.32% | 약 5분 13초 |
| 5개 | 0.40% | 약 4분 10초 |

## 후속 안건

1. `base-increase-per-altar` 기본값을 코드 기본값과 문서 기본값 모두 `0.08`로 변경할지 결정
2. 기존 서버의 `game.yml`이 이미 `0.2`로 생성된 경우 운영자가 수동 수정해야 함을 운영 가이드에 추가
3. 3판 이상 테스트 후 평균 승리 시간이 8분 미만이면 `0.06~0.07`로 하향
4. 평균 승리 시간이 15분 이상이면 `0.09~0.10`으로 상향
5. 풀점령이 여전히 너무 강하면 `max-increase-per-second` 상한 공식 도입 검토

## 테스트 체크리스트

- [ ] 서비스 테스트/통계 시뮬레이션으로 제단 1~5개 점령 시간 확인
- [ ] 2인 테스트에서 제단 탈환 시 상승 속도 하락 확인
- [ ] 실제 4인 이상 테스트에서 평균 승리 시간 기록
- [ ] 5개 풀점령 상태에서도 최소 3분 이상 반격 시간이 있는지 확인
- [ ] 승리 후 결과 통계의 플레이 타임과 실제 체감 시간이 일치하는지 확인
