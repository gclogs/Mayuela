# 운영자 명령어 가이드

## 문서 역할

Mayuela 서버 운영자가 게임을 준비하고 시작하기 위해 따라야 하는 명령어 절차를 정리합니다.

## 사전 조건

- Paper `1.21.11` 서버에서 플러그인을 실행합니다.
- 운영자는 `mayuela.admin` 권한을 가지고 있어야 합니다.
- 최소 1개 이상의 맵과 제단을 등록해야 게임을 시작할 수 있습니다.
- 게임 스폰 위치를 등록해야 게임을 시작할 수 있습니다.
- 게임 시작 인원은 4명 이상, 10명 이하, 짝수 인원이어야 합니다.

## 1. 로비 등록

플레이어를 게임 시작 전 이동시킬 로비 위치에서 실행합니다.

```text
/입장 로비등록
```

결과:

- 현재 위치가 `game.yml`의 `lobby`에 저장됩니다.
- `lobby.enabled`가 `true`가 됩니다.
- `READY` 세션 진입 시 참가자가 해당 위치로 텔레포트됩니다.

## 2. 게임 스폰 등록

실제 전투가 시작될 위치에서 실행합니다.

```text
/game 스폰등록
```

결과:

- 현재 위치가 `game.yml`의 `game-spawn`에 저장됩니다.
- `READY` 카운트다운이 끝나고 `PLAYING`으로 전환될 때 모든 참가자가 해당 위치로 텔레포트됩니다.
- 이 위치가 등록되지 않으면 `/game 시작`이 실패합니다.

## 3. 맵 등록

맵 영역의 첫 번째 지점에서 실행합니다.

```text
/game 맵 pos1
```

맵 영역의 두 번째 지점에서 실행합니다.

```text
/game 맵 pos2
```

맵을 저장합니다.

```text
/game 맵 저장 mayuela_01
```

결과:

- `maps.yml`에 맵 이름, 월드, `position1`, `position2`가 저장됩니다.

## 4. 제단 등록

제단으로 사용할 신호기 또는 신호기 바로 위 설치 위치를 바라보고 실행합니다.

```text
/game 제단등록 altar_1
```

여러 제단을 등록할 수 있습니다.

```text
/game 제단등록 altar_2
/game 제단등록 altar_3
```

제단 목록 확인:

```text
/game 제단목록
```

결과:

- `alter.yml`에 제단 이름, 월드, 좌표가 저장됩니다.
- 바라본 블록이 신호기이면 신호기 좌표가 저장됩니다.
- 바라본 블록 아래가 신호기이면 아래 신호기 좌표가 저장됩니다.
- 명령어로 등록된 제단 목록을 확인할 수 있습니다.

## 5. 상점 위치 등록

상점 NPC 또는 코인 드롭 기준 위치에서 실행합니다.

```text
/game 상점등록
```

결과:

- `game.yml`에 상점 위치가 저장됩니다.
- 게임 중 코인은 등록된 맵 안 랜덤 지상 위치에 드롭됩니다.
- 플레이어는 `/상점열기` 또는 `/상점열기` 명령어로 은행 GUI를 열 수 있습니다.
- 게임 진행 중에는 F키로도 은행 GUI를 열 수 있으며, 보조 손 교체는 취소됩니다.
- 은행에서는 화살 1개, 밀치기 막대기, 점프강화 아이템, 밀치기 저항 아이템을 구매할 수 있습니다.
- 구매 비용은 인벤토리에 있는 `Mayuela 코인` 아이템에서 차감됩니다.

## 6. 플레이어 입장

플레이어는 다음 명령어로 게임에 참가합니다.

```text
/입장
```

결과:

- 참가자 목록에 등록됩니다.
- 색상은 아직 배정되지 않고 `준비` 상태로 표시됩니다.
- 스코어보드에는 `[플레이어 이름] >> 준비`가 표시됩니다.
- 참가자들에게 현재 모인 인원 수가 안내됩니다.

준비를 취소하려면 다음 명령어를 사용합니다.

```text
/퇴장
```

퇴장 규칙:

- `WAITING` 상태에서만 사용할 수 있습니다.
- 게임 종료 후에도 참가자는 `준비` 상태로 남아 있으므로, 준비를 취소하려면 `/퇴장`을 입력해야 합니다.
- 퇴장 시 참가자들에게 현재 모인 인원 수가 안내됩니다.
- `WAITING` 중 서버 접속을 종료하면 `/퇴장`을 입력하지 않아도 Mayuela 참가자에서 자동 제외됩니다.
- `READY` 또는 `PLAYING` 중 서버 접속을 종료하면 참가/팀/진행률 상태는 유지되며, 재접속 시 복구됩니다.

## 7. 팀 수동 지정

운영자는 게임 시작 전 특정 플레이어를 원하는 색상 팀으로 지정할 수 있습니다.

```text
/game 팀지정 <플레이어> <색상>
```

예시:

```text
/game 팀지정 PlayerA 빨강
/game 팀지정 PlayerB 빨강
/game 팀지정 PlayerC 노랑
```

규칙:

- 한 색상 팀에는 최대 2명까지만 지정할 수 있습니다.
- 1명만 지정된 색상 팀은 게임 시작 시 미지정 플레이어 1명을 무작위로 채워 2명 팀이 됩니다.
- 수동 지정되지 않은 플레이어는 `/game 시작` 시 무작위로 2명씩 팀이 됩니다.
- 수동 지정을 취소하려면 `/game 팀해제 <플레이어>`를 사용합니다.

```text
/game 팀해제 PlayerA
```

## 8. 게임 시작

운영자가 실행합니다.

```text
/game 팀전 시작
/game 개인전 시작
/game 시작
```

`/game 시작`은 기존 호환을 위해 `/game 팀전 시작`과 동일하게 동작합니다.

시작 조건:

- 팀전은 참가 플레이어가 4명 이상이어야 합니다.
- 팀전은 참가 플레이어 수가 짝수여야 합니다.
- 개인전은 참가 플레이어가 2명 이상이어야 합니다.
- 참가 플레이어가 10명을 초과하면 시작할 수 없습니다.
- 등록된 맵이 1개 이상이어야 합니다.
- 등록된 제단이 1개 이상이어야 합니다.
- 게임 스폰 위치가 등록되어 있어야 합니다.

결과:

- `READY` 세션으로 전환됩니다.
- 팀전은 수동 지정된 팀을 우선 반영하고, 남은 플레이어는 무작위로 2명 단위 팀에 편성됩니다.
- 개인전은 참가자마다 1명짜리 팀을 만들고 각자 다른 색상을 배정합니다.
- 이 시점에 팀 색상과 색유리가 확정됩니다.
- 게임 중 스코어보드에서 본인의 팀 색상과 팀원을 확인할 수 있습니다.
- 기본 아이템이 지급됩니다.
- 이동속도 II 버프가 게임 종료까지 적용됩니다.
- 색깔 블록이 핫바 9번 슬롯에 고정됩니다.
- 카운트다운 후 `PLAYING` 세션으로 전환됩니다.

## 9. 운영 모니터링

게임 상태와 필드 코인 수를 확인합니다.

```text
/game 모니터링
```

표시 항목:

- 현재 세션 상태
- 등록된 제단 수
- 게임 스폰 등록 여부
- 필드에 남아 있는 Mayuela 코인 수와 최대 제한
- 코인 자동 제거 시간
- 밀치기 막대기 거리 설정

## 10. PDC 태그 확인

운영자는 손에 든 아이템 또는 인벤토리의 Mayuela PDC 태그를 확인할 수 있습니다.

```text
/game pdc
/game pdc 인벤토리
```

`/game pdc`는 메인핸드와 보조손 아이템의 PDC 태그를 출력합니다.  
`/game pdc 인벤토리`는 인벤토리 전체에서 `mayuela` 네임스페이스 PDC 태그가 있는 아이템만 출력합니다.

주요 확인 대상:

- 제단 설치기: `mayuela:color_block`, `mayuela:flag_itemsadder_id`
- 상점 아이템: `mayuela:shop_item`, `mayuela:shop_itemsadder_id`
- 코인: `mayuela:coin`
- F 슬롯 상점 아이템: `mayuela:offhand_lock`, `mayuela:offhand_itemsadder_id`

## 11. 설정 리로드

서버를 재시작하지 않고 YAML 설정 파일을 다시 읽습니다.

```text
/game reload
```

같은 동작으로 `/game 리로드`도 사용할 수 있습니다.

다시 읽는 파일:

- `game.yml`
- `alter.yml`
- `maps.yml`
- `model.yml`

제약:

- 게임 상태가 `WAITING`일 때만 실행할 수 있습니다.
- `READY`, `PLAYING`, `ENDING`, `RESETTING` 중에는 실행할 수 없습니다.
- 게임 중 설정을 바꾸면 코인 스케줄, 제단 점령 상태, 팀 상태가 서로 어긋날 수 있으므로 `/game 종료` 후 실행합니다.

결과:

- `game.yml`의 코인, 버프, 스폰, 상점, 로비 설정을 다시 읽습니다.
- `alter.yml`의 제단 목록을 메모리에 다시 반영합니다.
- `maps.yml`의 맵 목록은 다음 `/game 시작` 검증부터 다시 반영됩니다.
- `model.yml`의 팀별 제단 설치기와 상점 아이템 ItemsAdder id는 다음 지급/갱신 시 반영됩니다.

## 12. 코인 드롭 설정

인원별 코인 드롭 주기와 금액을 설정합니다.

```text
/game 코인설정 <1-10> <주기초> <금액>
```

예시:

```text
/game 코인설정 4 8 4
/game 코인설정 5 8 4
/game 코인설정 10 5 7
```

코인 룰은 실제 게임 참가자 수를 1~10 사이로 정규화해 `coin.rules.<인원수>`를 사용합니다.  
예를 들어 5명이 시작하면 `coin.rules.5`가 적용됩니다. 해당 룰이 없으면 `coin.drop-amount` 기본값으로 떨어질 수 있으므로 1~10명 룰을 모두 관리합니다.

필드 코인의 자동 제거 시간을 설정합니다.

```text
/game 코인제거 30
```

필드 코인 최대 개수를 설정합니다.

```text
/game 코인최대 40
```

코인은 등록된 맵 안에서 온라인 참가자 주변을 기준으로 탐색하며, 공중/물/나뭇잎 위에는 드롭하지 않습니다.
게임 중 코인을 주우면 `Mayuela 코인` 아이템이 플레이어 인벤토리에 들어갑니다.
획득한 `Mayuela 코인`은 버릴 수 없으며, 타인에게 양도할 수 없습니다.
필드에 플러그인이 생성해 추적 중인 코인만 획득 처리됩니다.

## 13. 은행 상점

게임 진행 중 참가자는 은행 GUI를 열 수 있습니다.

```text
/상점열기
/상점열기
```

판매 아이템:

- 밀치기 막대기: 타격한 상대를 `item.knockback-stick-blocks` 설정값 기준으로 밀칩니다.
- 밀치기 막대기: 플레이어당 `shop.knockback-stick-max-held` 설정값까지만 보유할 수 있습니다.
- 점프강화 아이템: 우클릭 시 점프 강화 버프가 적용되고 1개 소모됩니다.
- 밀치기 저항 아이템: 우클릭 시 일정 시간 밀치기 막대기 효과를 무시하고 1개 소모됩니다.

가격과 지속 시간은 `game.yml`의 `shop.*` 설정으로 관리합니다.

## 14. 밀치기 막대기 설정

밀치기 막대기 효과 거리를 설정합니다.

```text
/game 넉백설정 15
```

현재 값은 `game.yml`에 저장되며, 은행에서 구매한 밀치기 막대기 효과에 사용됩니다.

밀치기 막대기 보유 한도를 설정합니다.

```text
/game 막대기최대 3
```

현재 값은 `game.yml`의 `shop.knockback-stick-max-held`에 저장되며, 한도에 도달한 플레이어는 은행에서 밀치기 막대기를 추가 구매할 수 없습니다.

## 15. 게임 종료

게임을 강제로 종료해야 할 때 실행합니다.

```text
/game 종료
```

결과:

- scheduler task가 중지됩니다.
- Display 엔티티가 제거됩니다.
- 게임 진행용 스코어보드와 보스바가 정리되고, 참가자는 다시 `준비` 스코어보드로 표시됩니다.
- 제단 런타임 상태가 초기화됩니다.
- 게임 중 지급된 아이템, 갑옷, 이동속도/힘 버프가 정리됩니다.
- 모든 참가자가 등록된 게임 스폰 위치로 돌아갑니다.
- 참가자는 자동 퇴장되지 않습니다. 준비를 취소하려면 `/퇴장`을 입력합니다.

## 문제 해결

| 문제 | 확인할 것 |
| --- | --- |
| 게임이 시작되지 않음 | 4명 이상 짝수 인원, 맵 등록, 제단 등록, 게임 스폰 등록 여부 |
| 코인이 드롭되지 않음 | 맵 안 온라인 참가자 위치, 최대 필드 코인 수, `/game 모니터링` 결과 |
| YAML 수정이 반영되지 않음 | 게임 상태가 `WAITING`인지 확인 후 `/game reload` 실행 |
| 제단 점령이 안 됨 | 게임이 `PLAYING` 상태인지, 등록된 제단 위치인지 확인 |
| 색깔 블록이 사라짐 | 리스폰 후 9번 슬롯 복구 여부 확인 |
| Display가 남아 있음 | `/game 종료` 실행 후 제거 여부 확인 |
