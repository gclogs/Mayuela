# 매치 통계 이벤트 데이터

## 목적

Mayuela의 밸런스 조정과 시뮬레이션 보정을 위해 실제 매치에서 발생한 이벤트 시점 데이터를 저장합니다.

저장 위치:

```text
plugins/Mayuela/stats/matches/<match-id>.yml
```

## 저장 방식

- 게임 시작 시 `MatchStatsService`가 매치 통계를 시작합니다.
- 게임 시작 직후 `CRITICAL` 시작 이벤트를 먼저 체크포인트 저장합니다.
- 게임 중에는 메모리에 이벤트와 1초 단위 스냅샷을 누적합니다.
- 게임 종료, 승리, 강제 종료 시 같은 YAML 파일을 최종 데이터로 덮어씁니다.
- TPS 보호를 위해 매 tick 디스크 저장은 하지 않습니다.
- `stats.excluded-player-names`에 등록된 플레이어는 밸런스 통계에서 제외합니다. 기본 제외 대상은 `Gaensta`입니다.

## 데이터 품질 규칙

- 잠수, 테스트 방치, 비정상 플레이로 밸런스 해석을 왜곡하는 플레이어는 `game.yml`의 `stats.excluded-player-names`에 등록합니다.
- 제외 플레이어의 코인 획득, 상점 구매, 제단 점령/파괴, 사망, 밀치기 이벤트는 통계 이벤트에 저장하지 않습니다.
- 팀 최종 데이터의 `members`에서도 제외 플레이어는 빠집니다.
- 코인 설정은 `match.settings.coin.active-rule-player-count`, `coin.active-rule.*`, `coin.rules`에 같이 저장합니다.
- 5명 게임은 `coin.rules.5`를 사용합니다. 과거 +5 코인 기록은 `coin.rules.5`가 없어서 `coin.drop-amount: 5`로 fallback된 결과입니다.

## 이벤트 레벨

| 레벨 | 의미 | 저장 정책 |
| --- | --- | --- |
| `CRITICAL` | 매치 시작, 매치 종료, 승리 조건 | 항상 저장, 파일 상단 이벤트에 먼저 배치 |
| `HIGH` | 밸런스 분석 핵심 이벤트 | 항상 저장 |
| `NORMAL` | 흐름 해석용 이벤트 | 최대 5000개 유지 |
| `LOW` | 보조 맥락 이벤트 | 최대 1000개 유지 |

저장 파일의 `events` 목록은 `CRITICAL -> HIGH -> NORMAL -> LOW` 순서로 정렬됩니다.  
따라서 파일이 커지더라도 가장 중요한 이벤트가 먼저 확인됩니다.

## 현재 기록 이벤트

| 이벤트 | 레벨 | 의미 |
| --- | --- | --- |
| `MATCH_STARTED` | `CRITICAL` | 매치 시작, 설정값, 참가자, 팀 정보 |
| `MATCH_FINISHED` | `CRITICAL` | 승리 또는 강제 종료 |
| `ALTAR_TAKEN` | `HIGH` | 다른 팀 제단 탈환 |
| `ALTAR_BROKEN` | `HIGH` | 제단 파괴 |
| `COIN_PICKED_UP` | `HIGH` | 필드 코인 획득 |
| `SHOP_PURCHASED` | `HIGH` | 상점 구매 성공 |
| `SHOP_PURCHASE_FAILED` | `HIGH` | 코인 부족 등 구매 실패 |
| `PLAYER_DEATH` | `HIGH` | 플레이어 사망 |
| `ALTAR_CAPTURED` | `NORMAL` | 빈 제단 점령 |
| `ALTAR_REFRESHED` | `NORMAL` | 같은 팀 제단 재설치 시도 |
| `COIN_DROPPED` | `NORMAL` | 필드 코인 생성 |
| `COIN_EXPIRED` | `NORMAL` | 필드 코인 만료 |
| `SHOP_ITEM_USED` | `NORMAL` | 점프강화/밀치기 저항 사용 |
| `KNOCKBACK_HIT` | `NORMAL` | 밀치기 막대기 적중 |
| `KNOCKBACK_RESISTED` | `NORMAL` | 밀치기 저항으로 방어 |
| `STRENGTH_GRANTED` | `NORMAL` | 제단 미점령 팀 힘 버프 지급 |
| `PLAYER_JOINED` | `LOW` | 게임 중 재접속 |
| `PLAYER_QUIT` | `LOW` | 게임 중 접속 종료 |

## 스냅샷

`snapshots`는 1초 단위로 저장됩니다.

포함 항목:

- 경과 시간
- 필드 코인 수
- 팀별 활성화율
- 팀별 보유 제단 수
- 팀별 점령 누적 시간
- 팀별 제단 미점령 시간
- 힘 버프 활성 상태

이 스냅샷은 “게임이 왜 빨리 끝났는지”를 분석하는 핵심 데이터입니다.

## 분석 기준

통계 파일을 보면 다음 질문에 답할 수 있어야 합니다.

- 승리 팀이 평균 몇 개의 제단을 유지했는가?
- 제단 탈환이 충분히 자주 일어났는가?
- 코인이 너무 많이 생성되거나 너무 적게 회수되었는가?
- 상점 아이템이 실제 교전에 얼마나 자주 쓰였는가?
- 사망이 특정 아이템이나 특정 구간에 몰렸는가?
- 게임 종료 직전 1위 견제가 작동했는가?

## 성능 원칙

- 이벤트는 발생 시점에 메모리에만 기록합니다.
- 종료 시점에만 YAML 파일을 저장합니다.
- `CRITICAL`, `HIGH` 이벤트는 삭제하지 않습니다.
- `NORMAL`, `LOW` 이벤트는 상한을 두어 긴 게임에서도 메모리 사용량이 과도하게 증가하지 않도록 합니다.
