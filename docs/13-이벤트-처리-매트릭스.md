# 이벤트 처리 매트릭스

## 문서 역할

Paper/Bukkit 이벤트를 어떤 Listener가 받고 어떤 Service로 위임하는지 정의합니다.  
리스너가 비즈니스 로직을 직접 많이 가지지 않도록 경계를 명확히 합니다.

## 처리 원칙

- Listener는 이벤트 검증과 서비스 위임만 담당합니다.
- 게임 규칙은 Service에서 처리합니다.
- 이벤트 취소가 필요한 경우 Listener에서 `event.setCancelled(true)`를 수행합니다.
- Bukkit/Paper API 호출은 기본적으로 메인 스레드에서 수행합니다.
- 파일 저장은 이벤트마다 즉시 수행하지 않고 필요한 시점에 모아서 처리합니다.

## 색깔 블록 잠금 이벤트 기준

다음 조건 중 하나에 해당하면 이벤트를 취소합니다.

- 아이템이 Mayuela 제단 색염료로 식별됨
- 클릭 슬롯이 핫바 4번 또는 보조 손 슬롯이고, 게임 참가자 상태임
- 드래그 대상 슬롯에 핫바 4번 또는 보조 손 슬롯이 포함됨
- 버리려는 아이템이 색깔 블록임
- 버리려는 아이템이 보조 손 잠금 아이템임
- 갑옷 슬롯을 클릭하거나 갑옷을 교체하려는 시도임

```java
event.setCancelled(true);
```

## 제단 점령 이벤트 기준

`PlayerInteractEvent`에서 신호기 클릭 시 다음 조건을 확인합니다.

- 게임 세션이 `PLAYING`인가
- 플레이어가 참가자인가
- 손에 든 아이템이 플레이어 팀 색염료인가
- 클릭한 신호기가 등록된 제단 위치인가

조건을 만족하면 서버가 신호기 위에 팀 색유리를 설치한 뒤 `AltarService.captureAltar()`로 위임합니다.  
조건을 만족하지 않으면 실패 사유를 플레이어에게 안내합니다.
같은 tick에 같은 플레이어 또는 같은 신호기에 설치 예약이 이미 있으면 추가 예약은 조용히 무시합니다.

## 제단 파괴 이벤트 기준

`BlockBreakEvent`에서 다음 조건을 확인합니다.

- 게임 세션이 `PLAYING`인가
- 플레이어가 참가자인가
- 파괴 대상 블록이 등록된 제단의 색깔 블록인가

조건을 만족하면 `AltarService.breakAltarBlock()`으로 위임해 점령 상태, 스코어보드, lore, `TextDisplay`, 발광 효과를 즉시 갱신합니다.
파괴된 제단 색깔 블록은 아이템으로 드롭되지 않으며, 기존 소유자와 파괴자에게 안내 메시지를 보냅니다.
