# 확장 개발 플레이북

이 문서는 Mayuela에 기능을 추가하거나 수정할 때 따라야 할 실무 절차입니다.

## 공통 개발 순서

1. 요구사항을 한 문장으로 고정합니다.
2. 영향을 받는 상태 소유자를 찾습니다.
3. 이벤트 시점을 찾습니다.
4. 설정값이 필요한지 판단합니다.
5. 통계 저장이 필요한지 판단합니다.
6. UI/메시지/DisplayEntity/스코어보드 반영 범위를 정합니다.
7. 실패/취소/종료/재접속 경로를 먼저 설계합니다.
8. 구현합니다.
9. `compileJava`를 실행합니다.
10. Paper 테스트 서버에서 QA 체크리스트를 돌립니다.
11. 문서와 변경로그를 갱신합니다.

## 기능별 수정 위치

### 새 상점 아이템 추가

수정 후보:

- `ConfigRepository`
- `ShopService.ShopItem`
- `ShopService.price()`
- `ShopService.open()`
- `ShopItemListener`
- `model.yml` 기본값
- `MatchStatsService`
- `docs/06-아이템-상점-코인.md`
- `docs/운영자-명령어-가이드.md`

체크:

- 가격 설정이 `game.yml`에 있는가?
- ItemsAdder id가 `model.yml`에 있는가?
- fallback material이 유효한가?
- 구매 실패 사유가 통계에 남는가?
- 아이템 사용 이벤트가 중복 발동하지 않는가?
- 아이템 사용 후 소모/쿨다운/보유 한계가 있는가?

### 새 PDC 태그 추가

수정 후보:

- 아이템 생성 서비스
- 아이템 판별 서비스
- `PdcMonitorService`
- 운영자 문서

체크:

- PDC key namespace가 `mayuela`인가?
- 타입이 명확한가? `STRING`, `INTEGER`, `BYTE` 등
- PDC 없이 들어온 fallback 아이템을 거부하는가?
- 운영자가 `/game pdc 인벤토리`로 확인 가능한가?

### 새 DisplayEntity 추가

수정 후보:

- `DisplayService`
- 관련 서비스의 상태 변경 지점
- `GameSessionService.forceStop()`
- 재접속/리스폰 복구 지점

체크:

- 생성 위치가 명확한가?
- teleport 또는 text update 주기가 필요한가?
- 제거 조건이 모두 있는가?
- plugin disable 시 제거되는가?
- 최대 개수가 계산되어 있는가?

### 코인 밸런스 변경

수정 후보:

- `ConfigRepository`
- `CoinService`
- `GameCommand`
- `MatchStatsService`
- `docs/코인-드랍-공평성-모니터링.md`

체크:

- 인원수별 룰이 1~10명 모두 있는가?
- 변경된 룰이 `/game 모니터링`에 보이는가?
- 매치 통계에 설정값이 저장되는가?
- 코인 드랍 속도와 상점 가격이 같은 단위로 분석되는가?
- 코인 최대 필드 수가 TPS 예산 안에 있는가?

### 현상수배 밸런스 변경

수정 후보:

- `ConfigRepository`
- `AltarService`
- `PlayerLifecycleListener`
- `ScoreboardService`
- `DisplayService`
- `GameCommand`
- `MatchStatsService`
- `docs/현상수배-리드격차-설계.md`

체크:

- 일반 플레이어에게 리드 격차를 노출하지 않는가?
- `/game 모니터링`에는 리드 격차와 발동 가능 여부가 보이는가?
- 발동 기준과 해제 기준이 다르게 유지되는가?
- 보상 코인은 설정값을 사용하는가?
- 보상 1회 제한이 유지되는가?
- 현상수배 해제 시 보상 지급 이력이 초기화되는가?

### 팀/매치 모드 변경

수정 후보:

- `TeamService`
- `GameSessionService.startBlockReasons()`
- `JoinCommand`
- `LeaveCommand`
- `ScoreboardService`
- 테스트 시나리오 문서

체크:

- 팀전과 개인전 시작 조건이 분리되어 있는가?
- 홀수 인원 제한이 팀전에만 적용되는가?
- 수동 팀 지정이 랜덤 배정과 충돌하지 않는가?
- 게임 종료 후 팀/참가자 상태가 예상대로 남는가?

## 이벤트 시점별 플레이북

### 게임 시작

순서:

1. 시작 조건 검사
2. 팀 구성
3. READY 진입
4. 시작 아이템 지급
5. READY 카운트다운
6. PLAYING 진입
7. 통계 시작
8. 제단/코인/Display 초기화
9. 활성화율 스케줄러 시작

주의:

- 통계 시작 전 발생한 이벤트는 기록되지 않을 수 있습니다.
- READY에서 아이템 설치/드롭이 가능하면 안 됩니다.

### 제단 설치

순서:

1. 신호기 우클릭 감지
2. 신호기 GUI 차단
3. 플레이어 팀 확인
4. 등록 제단 위치 확인
5. 서버가 제단 블록 강제 설치
6. 이전 소유자 해제
7. 새 소유자 등록
8. 힘 버프 제거
9. 아이템 lore/스코어보드/TextDisplay 갱신
10. 현상수배 평가
11. 통계 기록

주의:

- 블록 직접 설치 이벤트에 의존하면 고스트 블록이 재발할 수 있습니다.

### 제단 파괴

순서:

1. 파괴 블록이 점령 제단인지 확인
2. 일반 블록이면 취소
3. 제단이면 드랍 방지
4. 소유자 해제
5. 아이템 lore/스코어보드/TextDisplay 갱신
6. 현상수배 평가
7. 통계 기록

주의:

- 곡괭이 요구사항은 제거되었습니다.

### 코인 드랍

순서:

1. 만료 코인 정리
2. 최대 필드 코인 수 확인
3. 맵 안 온라인 참가자 후보 수집
4. 앵커 플레이어 랜덤 선택
5. 지상 위치 탐색
6. ItemsAdder/fallback 코인 생성
7. Item 엔티티 드랍
8. glow 적용
9. TextDisplay 생성
10. 추적 맵 저장
11. 통계 기록

주의:

- 코인 TextDisplay는 코인과 함께 제거되어야 합니다.

### 코인 획득

순서:

1. Item 엔티티가 Mayuela 코인인지 확인
2. 추적 중인 필드 코인인지 확인
3. pickup 이벤트 취소
4. 인벤토리 공간 확인
5. 인벤토리에 코인 지급
6. `GamePlayer` 코인 증가
7. 통계 기록
8. 필드 코인 추적 해제
9. Item 엔티티와 TextDisplay 제거

주의:

- 추적 중이 아닌 코인은 주워도 Mayuela 경제에 들어오면 안 됩니다.

### 사망/부활

순서:

1. 사망 드랍 제거
2. 인벤토리 유지
3. 사망 통계 기록
4. 현상수배 보상 평가
5. 자동 리스폰
6. 게임 스폰으로 이동
7. 인벤토리/버프/F 슬롯/제단 아이템 복구
8. 현상수배 glow/display 복구
9. 3초 이동 잠금
10. 5초 무적

주의:

- 부활 후 버프가 사라지는 회귀가 있었으므로 반드시 확인합니다.

## 통계 확장 규칙

밸런스에 영향을 주는 기능은 반드시 통계를 남깁니다.

추가 권장 이벤트:

- `BOUNTY_ACTIVATED`
- `BOUNTY_RELEASED`
- `BOUNTY_REWARD_GRANTED`
- `BOUNTY_REWARD_ALREADY_CLAIMED`
- `ITEM_LIMIT_REACHED`
- `DISPLAY_ENTITY_CLEANUP`

이벤트 데이터 기본 필드:

- elapsed-seconds
- player
- team-id
- amount 또는 value
- reason
- location이 필요하면 world/x/y/z/chunk

- 현상수배 old no-arg 메서드 제거

- `Mayuela.java` 조립 코드 정리
- 컴포넌트별 단위 테스트 확대
- 운영자 명령어 help 자동화
