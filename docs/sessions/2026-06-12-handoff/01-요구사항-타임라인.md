# 요구사항 타임라인

이 문서는 대화에서 누적된 요구사항을 시간순으로 정리하고, 현재 개발 기준을 명확히 구분합니다.

## 1. 초기 게임 컨셉

게임명은 `Mayuela`입니다. 원형은 땅따먹기류 점령 게임이며, `Rayuela`와 Minecraft를 합성한 이름입니다.

초기 핵심:

- 맵에 여러 제단을 배치합니다.
- 플레이어는 자기 색상 아이템으로 제단을 점령합니다.
- 제단을 점령할수록 팀의 누적 활성화율이 더 빨리 오릅니다.
- 누적 활성화율이 100%가 되면 승리합니다.
- 상점 NPC 또는 상점 명령어로 아이템을 구매합니다.
- 코인은 필드에서 획득합니다.
- 최대 인원은 10명입니다.

## 2. 맵과 세션

확정된 기준:

- 맵은 `position1`, `position2`로 등록합니다.
- 맵이 등록되어야 게임을 시작할 수 있습니다.
- 게임 스폰 위치도 별도 등록이 필요합니다.
- 스폰 위치가 없으면 게임을 시작할 수 없습니다.
- 참가자는 `/입장`으로 등록합니다.
- `/퇴장`은 준비 취소 역할을 합니다.
- 게임 종료 후 참가자들은 READY 상태로 돌아가며, `/퇴장`을 입력해야 준비가 취소됩니다.
- 게임 시작 시 READY 세션을 거쳐 준비 시간을 둡니다.

중요 변경:

- 과거에는 맵 밖 이동을 막는 `onMove` 경계 리스너를 고려했지만, 현재는 맵 밖 이동을 허용합니다.
- `PlayerMoveEvent`는 부활 직후 3초 이동 잠금 같은 제한된 목적에만 사용합니다.

## 3. 팀 구성

현재 기준:

- 팀전은 `2vs2`, `2vs2vs2`, `2vs2vs2vs2`, `2vs2vs2vs2vs2` 구조입니다.
- 팀전은 짝수 인원만 시작할 수 있습니다.
- 필수 인원은 4명 이상입니다.
- 권장 최대 인원은 10명입니다.
- 개인전 시작 명령도 존재합니다.
- 입장 시 바로 색상이 정해지지 않고 준비 상태로 등록됩니다.
- 관리자가 수동으로 색상을 지정하거나, 게임 시작 시 랜덤 배정됩니다.

## 4. 제단 시스템

현재 기준:

- 제단은 신호기 위에 설치됩니다.
- 제단 설치 아이템은 핫바 4번 슬롯에 고정됩니다.
- 제단 설치 아이템은 이동/드롭/교체할 수 없습니다.
- 신호기 우클릭 시 GUI를 열지 않고 서버가 강제로 신호기 위에 제단 블록을 설치합니다.
- 고스트 블록 방지를 위해 설치 입력은 블록 직접 설치가 아니라 제단 아이템 사용으로 처리합니다.
- 곡괭이는 제거되었습니다.
- 맨손, 검, 활 등 어떤 아이템으로도 제단 블록을 부술 수 있습니다.
- 게임 준비/진행 중 일반 블록 파괴는 차단합니다.
- 제단 블록을 부수면 블록 드랍이 나오지 않습니다.
- 제단이 파괴되면 TextDisplay와 활성화율 표시가 즉시 갱신됩니다.

활성화율 기준:

- 제단을 하나만 점령해도 활성화율은 오릅니다.
- 더 많은 제단을 점령할수록 활성화율 상승 속도가 빨라집니다.
- 현재 기본값은 `altar.base-increase-per-altar: 0.04` 계열입니다.

## 5. 아이템과 상점

기본 지급:

- 팀 색상 가죽 갑옷 세트
- 철 검
- 활
- 화살은 기본 1개 지급 또는 상점 구매 기준으로 조정됨
- 이동속도 II 버프
- 제단 설치 아이템
- F 슬롯 상점 잠금/열기 아이템

상점:

- F 키 또는 명령어로 상점을 엽니다.
- 구매는 필드에서 주운 Mayuela 코인으로만 가능합니다.
- 코인은 버릴 수 없습니다.
- 타인에게 양도할 수 없습니다.
- 상점 아이템은 `model.yml`로 ItemsAdder 연동 가능합니다.

현재 상점 아이템:

- 화살 1개
- 밀치기 막대기
- 점프강화 아이템
- 밀치기 저항 아이템

밀치기 막대기:

- 플레이어 또는 엔티티 타격 시 1개 소모되어야 합니다.
- 보유 수량 제한이 있습니다.
- 힘 버프가 막대기 효과에 적용되면 안 됩니다.
- 스폰 무적 대상자를 반복 타격하면 공격자에게 속박이 걸리는 방어 로직이 있습니다.

## 6. 코인 시스템

초기에는 상점 NPC가 코인을 배급한다는 표현이 있었으나, 현재 기준은 다음과 같습니다.

- 필드에 코인이 드랍됩니다.
- 플레이어 인벤토리로 실제 코인 아이템이 들어옵니다.
- 필드에서 생성되어 추적 중인 코인만 획득 대상으로 봅니다.
- 코인은 랜덤 온라인 참가자 1명을 앵커로 선택한 뒤, 해당 플레이어 주변 지상에 드랍됩니다.
- 청크 단위 균등 분배는 아닙니다.
- 코인은 `model.yml`의 `system-items.field_coin`으로 ItemsAdder 연동됩니다.
- 드랍된 코인은 발광 효과를 가지며, `n초 뒤 제거됩니다.` TextDisplay를 표시합니다.
- 코인 자동 제거 시간과 최대 필드 코인 수는 설정/운영 모니터링 대상입니다.

## 7. 부활과 스폰킬 방지

현재 기준:

- 낙하 피해는 없습니다.
- 죽으면 게임 스폰으로 이동합니다.
- 부활 후 3초 동안 이동할 수 없습니다.
- 이후 5초 동안 무적입니다.
- 부활 시 버프가 복구되어야 합니다.
- 인벤토리와 갑옷은 유지/복구되어야 합니다.
- 게임 종료 시 모든 아이템 상태가 초기화되어야 합니다.

## 8. 현상수배 시스템

중요 변경:

- 과거 기준: 제단 3개 이상 점령한 팀이 현상수배
- 현재 기준: 1등 팀이 2등과 의미 있는 리드 격차를 만들었을 때 현상수배

현재 확정값:

- 발동 격차: `10.0%`
- 해제 격차: `7.0%`
- 워밍업: `120초`
- 선두 최소 진행률: `20.0%`
- 상태 변경 쿨다운: `30초`
- 처치 보상: `8코인`

UI 정책:

- 일반 플레이어 메시지에는 리드 격차를 노출하지 않습니다.
- 스코어보드에는 현상수배 팀만 표시합니다.
- 머리 위에는 팀 색상 ItemDisplay 아래에 `현상수배` TextDisplay를 표시합니다.
- 리드 격차와 발동 가능 여부는 `/game 모니터링`에서만 확인합니다.

## 9. 통계와 모니터링

현재 기준:

- 매치 통계는 `plugins/mayuela/stats/matches/<match-id>.yml`에 저장됩니다.
- 중요 이벤트는 `CRITICAL`, `HIGH`, `NORMAL`, `LOW` 레벨로 나눕니다.
- 코인 드랍/획득/만료, 상점 구매, 제단 점령/파괴, 사망, 접속 종료, 버프 지급 등이 기록됩니다.
- 코인 공평성 분석을 위해 앵커 플레이어, 드랍 청크, 거리, 후보자 수를 저장합니다.
- 현상수배 설정값도 통계에 저장합니다.

## 10. 현재 문서 주의사항

기존 문서 일부에는 다음 오래된 기준이 남아 있을 수 있습니다.

- 현상수배가 제단 3개 이상 기준이라고 적힌 문서
- 제단 설치 아이템이 색유리/염료로 표현된 오래된 문장
- 곡괭이로만 제단을 부순다는 오래된 문장
- 일부 깨진 한글 인코딩

새 개발자는 이 세션 폴더와 실제 코드를 우선 기준으로 삼아야 합니다.
